## 现象

执行 `npx supabase db push --linked --yes` 时，Supabase CLI 在 Windows 用户目录写入 telemetry 临时文件失败，错误为 `EPERM`。将 CLI 配置目录重定向到临时目录后，CLI 又因新的配置目录没有登录凭据而返回 `Access token not provided`。

同一时间，Supabase Dashboard 显示技术故障提示。SQL Editor 页面可以加载并显示已登录的 postgres 角色，但在通过浏览器自动填写或运行较长 SQL 时持续超时，未能得到可靠的执行结果。后续通过 CLI 关闭遥测、恢复登录态并成功完成迁移，因此以 CLI 的迁移清单和集成测试作为最终证据。

## 可复现与恢复步骤

恢复后的标准命令为：

```powershell
$env:SUPABASE_ACCESS_TOKEN = "<仅在本机设置，不要提交或发送>"
npx.cmd supabase db push --linked --yes
```

如果仍然需要登录，应在本机执行 `npx supabase login`，完成登录后重新运行上面的迁移命令。也可以在 Supabase Dashboard 的 SQL Editor 中一次性执行该 migration 文件内容，但执行后必须通过 migration 目录记录和后续集成测试确认结果。

## 结论

远程迁移和集成验证已完成。以后遇到同类 Windows CLI 问题，先执行 `npx.cmd supabase telemetry disable`，再在本机恢复 CLI 登录态；迁移后必须运行处理模块集成测试并确认清理计数为零。
