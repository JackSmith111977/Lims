## 1. 最小可用入口

- `/` 只承担入口解析，不再渲染静态模块占位卡片。
- 未登录用户从 `/` 进入 `/login`；已登录用户从 `/` 进入 `/dashboard`。
- 登录成功后统一进入 `/dashboard`。`/dashboard` 是当前角色权限驱动的实际工作台。
- 工作台菜单按权限显示，接口继续执行服务端权限和 RLS 校验；无角色用户显示明确的初始化提示，不伪造业务数据。

## 2. 首个管理员初始化

- 不开放公开注册，不新增浏览器端 `signUp`；实验室账号由受控管理员流程创建，符合 `DES-AUTH-001` 的安全边界。
- 新增一次性运维脚本 [`docs/ops/initial-admin-bootstrap.md`](../../docs/ops/initial-admin-bootstrap.md) 和 `scripts/ops/bootstrap-admin.mjs`：使用正式项目 `.env.local` 中的 service role key 调用 Auth Admin API 创建或复用指定邮箱，再幂等分配 `SYSTEM_ADMIN`。
- 脚本只接受任务专用环境变量中的邮箱/初始密码，不把密码写入文件、日志或响应；已存在用户不重置密码、不删除既有角色。
- 脚本写入一次 `BOOTSTRAP_ADMIN` 审计事件，目标项目必须由执行人先核对；脚本不能替代应用内普通用户管理。
- 首个管理员完成登录后，后续用户统一从 `/admin/users` 创建并分配角色。

## 3. 旧设计清理边界

- 删除根页面中的“待接入”模块数组和“下一步配置认证”的过期文案；不删除已有业务页面、API、migration 或历史验收证据。
- 将已实施的 `ui.md`、数据模型和系统分析中的旧“Draft/下一步”表述改为当前状态或非 MVP 后续扩展。
- 真实仪器/传感器连接、外部 CA/HSM、通用公开注册和完整灾备恢复演练不纳入本次 MVP；保留其研究/运维文档并明确为后续范围。

## 4. 验收

- 未认证访问 `/` 最终进入 `/login`；认证后访问 `/` 最终进入 `/dashboard`。
- 首个管理员初始化可重复执行，不产生重复角色关联、不泄露密码，并能登录看到授权菜单。
- 管理员可从 `/admin/users` 创建普通用户；普通用户不能访问管理员页面。
- 旧入口文案不再出现；`Spec → Plan → Tasks → Implement → Verify` 和一致性门禁通过。
