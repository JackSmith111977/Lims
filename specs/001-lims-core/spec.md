## 1. 目标与范围

### 1.1 系统目标

系统应支持高校科研实验室围绕实验任务管理样品、人员、设备、实验方法、试剂耗材、实验数据、审核记录和报告，形成以下可追踪闭环：

```text
科研项目/实验需求
  → 任务登记与样品登记
  → 任务分配
  → 实验执行与数据获取
  → 数据处理
  → 结果审核
  → 报告生成
  → 统计、归档与历史查询
```

### 1.2 第一版范围

第一版必须包含：

- 用户、角色与权限
- 实验室人员
- 样品与样品流转
- 实验任务与任务分配
- 实验方法
- 实验数据与结果
- 数据审核
- 报告
- 仪器设备
- 试剂耗材
- 设施与环境基础记录
- 操作日志与数据追溯
- 基础统计和数据看板

### 1.3 明确不在基础交付范围

- 真实实验仪器的硬件控制和正式协议适配。
- ERP、MES、CRM、OA 等外部系统的正式联调。
- 多租户、跨实验室和跨地域部署。
- 完整的电子签名、法规认证和商业级合规体系。
- 复杂的人工智能预测、自动资源优化和预测性维护。

这些内容可以通过模拟数据、文件导入、接口预留或论文展望体现，但不能阻塞核心业务闭环。

## 3. 业务状态与流程

### 3.1 任务状态

```text
待登记 → 待分配 → 已分配 → 执行中 → 待审核 → 已通过 → 已归档
                                  ↘ 退回/待补充
```

每一次状态变化必须写入任务历史，包含变更前状态、变更后状态、操作人、时间和备注。

### 3.2 样品状态

```text
待登记 → 已登记 → 待处理 → 处理中 → 已处理 → 已归档/已处置
```

样品流转必须记录节点、时间、交接人员、位置和处理说明。

### 3.3 审核规则

- 待审核结果只能由项目负责人/教师或授权人员处理。
- 审核结果必须为通过、退回或要求补充之一。
- 审核不通过时，相关任务不能直接归档。
- 审核意见、审核人和审核时间必须保留。

## 5. 数据模型要求

### 5.1 核心实体

系统至少应包含以下实体：

- 用户、角色、权限、部门和岗位
- 实验室、实验组和科研项目
- 样品、样品流转记录
- 实验任务、任务分配记录
- 实验方法、方法版本
- 实验原始数据、处理数据和最终结果
- 审核记录、报告和报告版本
- 仪器设备、维护记录和校准记录
- 试剂、耗材和库存变动记录
- 设施、环境数据和环境提醒记录
- 文件附件、操作日志

### 5.2 关联要求

- 样品必须能够追溯到相关任务。
- 任务必须能够追溯到项目、人员和方法。
- 实验数据必须能够追溯到样品、任务、设备和采集时间。
- 报告必须能够追溯到审核记录和结果数据。
- 关键变更必须能够追溯到操作人和操作时间。
