# SDD 质量门禁

## G0 项目入口门禁

- [ ] `AGENTS.md` 存在并指向唯一 Spec。
- [ ] `specs/README.md` 和 `specs/constitution.md` 可读取。
- [ ] 文档职责没有重复事实源。

## G1 需求门禁

- [ ] 每条需求有唯一 ID、状态、优先级和来源。
- [ ] 每条 P0 需求有验收场景。
- [ ] 角色、权限、状态和异常路径已覆盖。
- [ ] 明确不做的内容已写入边界。
- [ ] 没有把技术方案误写成产品需求。

## G2 设计门禁

- [ ] 架构覆盖所有 P0 需求。
- [ ] 数据模型包含主键、外键、唯一性、状态和审计约束。
- [ ] API 契约包含成功、错误、认证和分页模型。
- [ ] 页面和接口均有权限映射。
- [ ] 迁移、备份、恢复和降级方案已说明。
- [ ] 设计记录了至少一个可替换边界。

## G3 实现门禁

- [ ] 代码任务包含 Spec ID 和验证方式。
- [ ] 关键业务规则在服务端执行。
- [ ] RLS、权限和审计逻辑已实现或有明确阻塞记录。
- [ ] migration 和配置变更已版本化。
- [ ] 单元、接口或组件测试已覆盖新增行为。

## G4 审查门禁

- [ ] 已完成独立或角色切换式对抗性审查。
- [ ] P0/P1 问题已关闭、修复或明确批准豁免。
- [ ] 没有破坏已有 API、数据约束或状态机。
- [ ] 没有新增未记录的越权、泄露、重复数据或恢复风险。

## G5 发布门禁

- [ ] 全量测试通过。
- [ ] 一致性检查通过。
- [ ] migration 可从空库和上一版本执行。
- [ ] 部署、演示和回滚说明已更新。
- [ ] CHANGELOG、版本号和 Spec 状态已更新。
