# 工作台导航可用性设计

| 项目 | 内容 |
| --- | --- |
| 设计 ID | `DES-DASHBOARD-NAV-001` |
| 状态 | Approved |
| 来源 | `FR-AUTH-002`、`FR-DASH-001～005`、`NFR-USE-001` |
| 关联页面 | `/dashboard` |
| 设计范围 | 仅优化工作台导航的信息架构、布局和交互，不改变业务权限、API 或数据模型 |

## 1. 问题与目标

当前工作台把所有可访问模块渲染为一条无分组的横向链接行，并混入已登录状态下价值较低的“返回系统首页”和“登录页”入口。在常见桌面宽度下链接被压缩成多行短文本，模块关系不清晰；在窄屏下会继续产生拥挤和横向滚动，影响点击和键盘操作。

本次优化目标：

- 按业务工作流和管理职责分组，降低一次性认知负担。
- 提高每个导航项的点击区域、行高、间距和当前项辨识度。
- 在桌面、平板和手机宽度下保持可读、可点击和不产生页面级横向滚动。
- 保留现有服务端权限过滤、路由地址和直接访问保护，不扩大权限范围。

## 2. 导航信息架构

工作台保留在品牌区和当前页面入口中；主体导航只展示当前用户有权限访问的业务模块。

| 分组 | 导航项 | 路由 |
| --- | --- | --- |
| 管理与配置 | 用户管理、角色与权限、基础设置、操作日志 | `/admin/users`、`/admin/roles`、`/admin/settings`、`/admin/audit` |
| 实验流程 | 科研项目、实验任务、样品登记、实验方法、实验数据 | `/projects`、`/tasks`、`/samples`、`/methods`、`/data` |
| 审核与报告 | 结果审核、实验报告 | `/reviews`、`/reports` |
| 资源管理 | 人员档案、设备档案、试剂耗材、环境监测 | `/personnel`、`/instruments`、`/inventory`、`/environment` |

已登录工作台不再把 `/` 或 `/login` 作为主体业务导航项：`/` 仍按现有会话解析规则进入 `/dashboard`，退出仍由顶部 `LogoutButton` 完成。

## 3. 布局与交互

- 导航使用独立的白色分组容器，桌面端按 4 个分组形成响应式网格；平板降为 2 列，手机降为单列。
- 每组显示组名和简短说明，组内导航项使用有边界的块级链接；每项保持至少 `44px` 的垂直点击区域。
- 当前路径及其子路径使用 `aria-current="page"`、高对比背景和边框强调；非当前项只在 hover/focus 时增强，不依赖颜色 alone。
- 使用 `focus-visible` 提供键盘焦点环；链接文本保持完整，不通过强制缩小字体或单字换行解决空间问题。
- 服务端先按已有权限计算可见项，再将已过滤的导航模型传入展示组件；无可见项的分组不渲染。
- 导航组件只负责呈现和当前路径识别，不直接读取 Supabase，不重新实现权限判断。

## 4. 非目标与兼容边界

- 不新增模块、权限、数据库字段、API 或业务操作。
- 不修改任何业务页面的 URL 和后端权限校验。
- 不引入图标库、侧边栏状态持久化、拖拽排序或移动端抽屉菜单；先用稳定的响应式分组满足 MVP 可用性。
- 不要求改变看板统计口径；看板主体继续复用 `DES-DASHBOARD-001`。

## 5. 验收依据

| 验收项 | 验证方式 |
| --- | --- |
| 只有拥有权限的导航项显示 | 现有角色权限逻辑 + 工作台服务端渲染检查 |
| 分组、顺序和路由正确 | 导航组件单元测试或静态断言 |
| 当前路径可识别且支持子路径 | Playwright 登录后访问 `/dashboard`、模块页和报告追溯页 |
| 桌面/平板/手机不出现导航拥挤 | Playwright 多视口截图/布局断言，人工检查截图 |
| 键盘和语义可用 | `nav`、组标题、链接、`aria-current`、focus-visible 检查 |
| 既有未认证和越权保护不回归 | `dashboard-access.spec.ts`、模块访问 E2E 和全量构建 |

## 6. 二次视觉密度优化记录（2026-07-19）

### 背景

首次导航分组已解决单行横向链接和权限混排问题，但实际页面仍需要进一步降低视觉噪声：外层容器、分组卡片和链接边框层级过多，标题区与入口区的间距也偏大。优化目标是让用户更快扫描分组和入口，同时保留完整文字、当前路径识别、键盘焦点和 44px 点击区域。

### 已确认方案

- 保留四类业务分组和服务端权限过滤，不改变入口数量、路由或权限语义。
- 使用一个轻量的导航面板承载分组，分组卡片采用低对比背景和统一内边距，减少重复阴影和重边框。
- 分组标题显示入口数量，链接统一为至少 `44px` 高的整行操作块；仅当前项使用明显的蓝色填充和左侧状态标记，普通项避免同时使用边框、箭头和强阴影。
- 桌面端保持四列，平板两列，手机一列；所有文字保持完整，不使用横向滚动、单字换行或折叠菜单。
- 对导航组件补充结构化 class 断言和多视口人工检查，重点验证 375px 无横向溢出、当前项可辨识和链接可点击。

### 非目标

本轮不引入图标库、侧边栏、抽屉、持久化状态、拖拽排序、业务模块或新的权限判断。

### 本轮验证记录

- `npm.cmd test`：23 个测试文件、95 个断言通过。
- `npm.cmd run lint`、`npm.cmd run build`：通过；构建仅输出本机 SWC 原生模块加载警告，未阻断编译、TypeScript 或静态生成。
- 生产构建服务上的未认证 E2E：18/18 通过；`check-consistency.ps1` 和 `check:versioning` 通过。
- 受控浏览器登录态检查：本地 `/api/v1/auth/login` 对测试账号返回 503，未进入工作台；该环境门禁未修改认证实现，也不作为 UI 视觉通过证据。
