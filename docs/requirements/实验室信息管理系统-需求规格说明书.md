## 1. 需求概览

系统面向高校科研实验室，采用 Web 管理系统形式，按 GB/T 40343—2021 的核心功能模型组织需求。

核心业务闭环为：

```text
任务登记与样品登记
  → 任务分配
  → 实验执行与数据获取
  → 数据处理
  → 数据审核
  → 报告生成
  → 统计、归档与追溯
```

## 2. 需求域索引

详细需求编号和验收条件请直接查看核心 Spec：

- `FR-AUTH-*`：用户与权限
- `FR-PER-*`：实验室人员
- `FR-SAMPLE-*`：样品与样品流转
- `FR-TASK-*`：实验任务与任务分配
- `FR-METHOD-*`：实验方法
- `FR-DATA-*`：实验数据与结果
- `FR-REVIEW-*`：数据审核
- `FR-REPORT-*`：报告管理
- `FR-EQUIP-*`：仪器设备
- `FR-INVENTORY-*`：试剂与耗材
- `FR-ENV-*`：设施与环境
- `FR-AUDIT-*`：日志与数据追溯
- `FR-DASH-*`：数据看板与统计
- `FR-SETTING-*`：系统设置
- `NFR-*`：非功能需求
- `AC-*`：验收场景

## 3. SRS 使用方式

1. 需求评审：阅读核心 Spec 的目标、角色、流程和需求表。
2. 系统设计：依据需求 ID 设计用例图、ER 图、接口和页面。
3. 编码实现：依据 `plan.md` 和 `tasks.md` 执行，不在本文件另建任务。
4. 测试验收：使用 `AC-*` 验收场景验证 `FR-*` 和 `NFR-*`。
5. 论文撰写：本文件可作为需求分析章节的阅读入口，具体内容引用核心 Spec。

## 4. 需求变更规则

如果发现需求缺失或需要修改：

1. 先修改 `specs/001-lims-core/spec.md`。
2. 更新 `specs/001-lims-core/traceability.md`。
3. 评估 `plan.md`、`tasks.md`、数据模型、测试和论文的影响。
4. 需要时再更新本视图的概览内容。
