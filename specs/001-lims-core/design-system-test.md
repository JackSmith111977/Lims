## 1. 测试目标

系统测试不只验证页面能打开，还要证明 Spec 的验收场景、权限边界、状态流转、数据追溯、审计、备份说明和演示清理可以在可复现环境中完成。测试证据必须包含命令、环境、数据前缀、结果、失败原因和复测入口。

## 2. 测试层级

| 层级 | 目标 | 入口 |
| --- | --- | --- |
| 单元/服务层 | 校验输入、状态机、不可变字段、聚合和错误模型 | `npm.cmd test` |
| 未认证 E2E | 验证页面/接口保护、认证错误和基础降级 | `npx.cmd playwright test` |
| 远程集成 | 验证真实 Supabase RLS、事务、审计、状态链和清理 | `npm.cmd run test:*integration` |
| 演示验收 | 用 `DEMO_` 合成数据走完 P0 业务闭环 | `docs/demo/demo-runbook.md` |
| 运维文档 | 验证备份、恢复、验证、密钥和回滚说明完整 | `npm.cmd run check:backup-docs` |

## 3. 进入和退出条件

进入条件：Spec/设计/任务已更新；migration 状态与代码基线一致；测试账号和环境变量通过本机配置提供；远程数据前缀已确认，不使用生产数据。

退出条件：所有 `AC-*` 有通过或已批准豁免证据；所有 P0/P1 审查问题关闭；单元、未认证 E2E 和必要远程集成通过；T-503D/T-505C 的临时数据和演示数据清理计数为 0；缺陷清单没有未处理的 P0/P1。

## 4. 安全和数据规则

- 测试凭据只存在本机环境变量或密码管理器中，日志和报告不包含 token、密码、连接串或真实个人数据。
- 远程集成使用时间戳/前缀隔离并在 `finally` 清理；遇到触发器阻断时使用受控 SQL，不用宽泛表清空。
- 演示数据只使用 `DEMO_` 前缀；演示环境与正式环境隔离，演示后用只读查询确认残留为 0。
- 失败测试保留最小化错误摘要和复现命令，不保留原始实验值或用户对象详情。

## 5. 证据状态

当前已具备单元测试、全量未认证 E2E、各模块历史远程集成记录、看板专项审查、备份文档检查和演示资产检查；尚未满足完整退出条件的项目在测试计划中标为 `Pending`，不能被“本地构建通过”替代。
