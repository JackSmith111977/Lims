# 科研项目与实验任务登记技术设计

| 项目 | 内容 |
| --- | --- |
| 设计编号 | DES-TASK-REGISTRATION-001 |
| 来源 Spec | `FR-TASK-001～002`、`NFR-SEC-001～002`、`NFR-DATA-001` |
| 状态 | Approved |
| 日期 | 2026-07-15 |

## 设计目标与边界

T-202 建立“科研项目 → 实验任务”的登记和查询闭环：项目保存项目编号、名称、负责人、说明、状态和周期；任务保存任务编号、名称、项目、方法版本、优先级、计划周期和说明，并支持查询已有样品关联。

本任务明确不实现：

- 任务分配、重新分配、任务状态流转和状态历史（T-205）。
- 样品登记、唯一编号和样品流转（T-203、T-204）。
- 实验方法的维护和版本管理（T-301）；任务只引用已有的有效方法版本。
- 设备、试剂耗材或结果数据关联（后续任务）。

## 架构和模块边界

```text
项目/任务页面
  └─ /api/v1/projects、/api/v1/tasks
       ├─ project service：research_project
       ├─ task service：experiment_task
       └─ sample link adapter：task_sample（只接收已有样品 ID）
```

- 项目和任务的校验、状态边界、引用检查和审计集中在 `src/lib/server/task-registration.ts`。
- Route Handler 只处理认证、HTTP 参数和响应转换。
- 任务状态在 T-202 中只读展示；禁止通过项目/任务登记接口直接修改，防止绕过 T-205 状态机。
- `method_id` 必须引用 `experiment_method.status = ACTIVE` 的方法版本；方法维护页面由 T-301 提供。

## 数据模型和完整性

复用现有表，不新增重复实体：

- `research_project`：`project_code` 唯一；`owner_id` 关联 `sys_user`；项目周期结束日期不得早于开始日期；归档项目不能接收新任务。
- `experiment_task`：`task_code` 唯一；关联项目和方法；优先级为 `LOW/NORMAL/HIGH`；计划结束不得早于开始日期；初始状态为 `DRAFT`。
- `task_sample`：任务与已有样品的联合关联，新增关联前校验样品属于同一项目；T-203 再提供样品侧维护入口。

项目和任务的创建、修改使用数据库现有外键、唯一约束、日期约束和更新时间触发器。停用/归档采用状态更新，不提供物理删除 API。

## API 契约

权限：

- `project.read`：查询项目及项目可见范围内的任务。
- `project.manage`：创建/修改项目；现有 RLS 允许项目负责人管理自己的项目。
- `task.read`：查询任务和任务已有样品关联。
- `task.manage`：创建/修改任务和任务-样品关联。

接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/projects` | 项目列表，支持 keyword/status/ownerId |
| POST | `/api/v1/projects` | 创建项目，ownerId 缺省为当前用户 |
| GET | `/api/v1/projects/{id}` | 项目详情及任务数量 |
| PATCH | `/api/v1/projects/{id}` | 修改项目登记字段，不改变任务状态 |
| GET | `/api/v1/tasks` | 任务列表，支持 keyword/projectId/status/priority |
| POST | `/api/v1/tasks` | 创建任务，可带已有 `sampleIds` |
| GET | `/api/v1/tasks/{id}` | 任务详情、项目/方法引用和样品关联 |
| PATCH | `/api/v1/tasks/{id}` | 修改登记字段；拒绝直接修改 status |

所有成功响应使用 `{ data: ... }`；失败使用 `{ error: { code, message } }`。创建和修改均服务端重复校验，数据库约束错误映射为稳定的 400/409 错误。

## 页面和交互

- `/projects`：项目列表、项目新建/编辑表单和项目任务数量。
- `/tasks`：任务列表、按项目/状态/优先级筛选和任务新建/编辑表单。
- 任务表单只允许选择已有项目和有效方法；当前 T-301 尚未完成时，方法使用已有方法 ID/引用数据，后续替换为方法选择器不改变 API。
- 任务状态显示为只读；分配入口和状态操作不在本页面显示。
- 表单提示项目归档、方法停用、日期倒置、重复编号和样品跨项目关联错误。

## 权限、安全和审计

- 项目和任务页面、API 分别执行认证和 `project.*`/`task.*` 权限校验；数据库 RLS 作为第二层边界。
- 创建任务前校验项目未归档、方法为 ACTIVE；不允许通过请求体覆盖 `created_at`、`updated_at` 或审计字段。
- 项目负责人字段只能引用存在且 ACTIVE 的 `sys_user`；任务登记不改变负责人角色和人员可用状态。
- 项目创建/修改、任务创建/修改及任务-样品关联变更调用 `record_audit_event`。
- 不记录密码、访问令牌或服务端密钥；审计前后值只包含业务登记字段。

## 异常、恢复和降级

- 未认证返回 401，无权限返回 403，不存在返回 404，重复编号返回 409，日期/引用/归档项目错误返回 400。
- 审计写入失败时整体业务操作失败，避免产生不可追溯数据。
- 任务状态更新、任务分配和状态历史由 T-205 接管；T-202 对请求体显式 `status` 返回稳定错误。
- 不使用缓存和异步队列；迁移只更新审计函数权限，项目/任务表结构保持兼容。

## 可扩展性和可维护性

- 项目和任务 API 使用独立服务函数，后续 T-203/204/205 可复用详情和关联适配器。
- 方法、样品和人员均通过外键/引用 ID 连接，避免跨模块复制名称。
- 列表筛选参数保持向后兼容；新增筛选使用可选 query 参数。
- 任务状态机和分配策略作为后续模块加入，不把状态规则散落到登记页面。

## 验证方式

- 单元测试：项目/任务 payload、日期/优先级/状态边界、状态字段拒绝和 query 参数。
- 未认证 E2E：项目和任务页面/API 返回登录跳转/401。
- 远程正向集成：创建/查询/修改项目和任务，重复编号、归档项目、停用方法、日期倒置、跨项目样品关联负向验证。
- 权限负向集成：只有 `project.manage`/`task.manage` 可写，普通实验人员按现有权限矩阵验证。
- 质量门禁：`tsc`、lint、Vitest、生产 build、Playwright、对抗性审查、`check-consistency.ps1` 和 `check:versioning`。
