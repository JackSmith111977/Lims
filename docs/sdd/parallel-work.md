# SDD 并行开发与集成规则

## 1. 并行原则

并行不是同时修改同一功能，而是把依赖明确、边界清晰的工作拆到不同工作流中。任何并行任务都必须在 `tasks.md` 中标记依赖和文件范围。

## 2. 推荐工作流

```text
主线：Spec / Plan / Tasks
  ├─ Stream A：数据库 migration 与数据访问
  ├─ Stream B：页面与交互
  ├─ Stream C：API Route Handlers 与校验
  └─ Stream D：测试、种子数据和文档
                 ↓
          集成分支统一验证
```

## 3. 任务标记

- `[P]`：允许并行。
- `[S]`：必须串行。
- `Depends: T-xxx`：依赖任务。
- `Files:`：预计修改路径。
- `Integration:`：集成时需要一起验证的任务。

只有满足以下条件的任务才能标记 `[P]`：

- 不修改同一核心文件。
- 不改变同一数据库表或 API 契约，或者已经先锁定契约。
- 不依赖未完成的迁移、类型或状态机。
- 有独立的验收方式。

## 4. 分支和工作区

- 分支格式：`feature/<spec-id>-<short-name>`、`fix/<issue-id>-<short-name>`、`docs/<topic>`。
- 每个并行工作流使用独立分支；必要时使用独立 worktree。
- 分支开始前先同步 Spec 和 Plan。
- 分支结束前必须更新任务状态和追踪矩阵。
- 合并顺序：契约/数据模型 → 服务层 → 页面 → 集成测试 → 文档。

## 5. 冲突处理

如果两个工作流需要修改同一文件：

1. 暂停后启动第二个任务，不强行并行。
2. 将共享内容拆成独立契约文件。
3. 由主线先合并接口、类型或 migration。
4. 下游工作流基于新主线重新同步。

## 6. 个人开发时的并行上限

本项目当前按单人开发设计：

- 默认一次只推进一个 P0 功能闭环。
- 最多同时保留两个未完成工作流。
- 同时开启多个 AI 会话时，必须分别指定任务 ID 和文件边界。
- 同一业务模块禁止多个会话同时修改。
