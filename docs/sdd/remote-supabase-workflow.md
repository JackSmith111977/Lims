## 1. 开始工作前的规范准入

开始任何需求、设计或编码工作前，按以下顺序读取：

1. `specs/README.md`：确认唯一事实源和 Spec → Plan → Tasks → Implement → Verify 流程。
2. `specs/constitution.md`：确认治理、追踪、状态和远程环境规则。
3. `specs/001-lims-core/spec.md`：确认需求 ID、边界、数据关系和验收条件。
4. 相关 `plan.md`、Design、API 契约、数据模型和 `tasks.md`：确认实现边界、依赖和文件边界。
5. `docs/sdd/README.md` 及当前阶段的规则/模板：确认调研、设计、任务、审查、质量和版本门禁。

完成读取后，任务或提交必须能指出对应的需求/验收 ID。发现规范缺失、过期或相互冲突时，暂停实现，先更新 Spec 和追踪产物。

## 2. 远程环境规则

- 开发联调、数据库迁移、远程集成测试、演示和验收统一使用经授权的远程 Supabase 项目。
- 本项目不要求启动本地 Supabase/Docker 数据库；本地单元测试可以使用 mock 或 fixture，但不能把本地结果写成远程验收证据。
- 演示和测试必须优先使用隔离项目或分支、合成数据和临时账号，不得把演示数据写入未经批准的生产环境。
- 每次远程操作开始前确认项目 ref、环境用途、备份/回滚路径、操作者授权和清理方案。

## 3. 受控浏览器操作

远程 Supabase Dashboard 的人工操作使用已登录的 Codex 受控浏览器：

1. 打开并确认 Supabase Dashboard 的项目和环境上下文。
2. 只执行本次任务所需的最小范围 SQL、迁移、查询或清理。
3. 从页面结果核对影响范围、执行结果和错误信息；失败后先重新读取页面状态，不盲目重复提交。
4. 完成后验证迁移版本、关键数据和清理计数，并把非敏感结果记录到审查或测试证据。
5. 结束时关闭不再需要的页面或标签，避免把已登录操作暴露给后续工作。

禁止读取、复制、回显或提交 Cookie、浏览器存储、会话信息、Token、Service Role Key、数据库密码和其他凭据。禁止使用无范围的 `delete`、`truncate`、`drop` 或批量清理；清理脚本必须有明确前缀、事务/回滚边界和残留核验。

## 4. 自动化例外

为保证迁移、集成测试和清理的可重复性，可以在获得授权后使用 Supabase CLI 或受控 API。自动化记录至少包含：

- 项目 ref 和环境用途；
- 命令或脚本路径、目标表/资源范围和临时数据前缀；
- 执行时间、结果摘要和失败信息；
- 迁移版本、断言结果、清理结果和残留计数；
- 不包含任何密钥、密码、会话或个人敏感信息。

自动化例外不能把本地数据库变成前置依赖，也不能绕过远程项目授权、RLS、审计、备份或清理要求。需要修改线上结构时，必须通过版本化 migration，并在远程项目中核验应用结果。

## 5. 最小证据清单

远程任务结束前，检查以下内容：

- [ ] 已读取规范入口和相关 Spec/Plan/Design/Tasks。
- [ ] 已记录需求或验收 ID、项目 ref、环境用途和授权边界。
- [ ] 已说明使用受控浏览器还是授权 CLI/API，以及原因。
- [ ] 已保存非敏感的执行结果、迁移版本、断言和错误信息。
- [ ] 临时用户、数据、文件和对象已清理，残留计数为 0 或已记录豁免。
- [ ] 已更新任务状态、追踪矩阵、测试依据和必要的审查记录。
- [ ] 已运行一致性、质量和版本相关门禁。
